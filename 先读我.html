你现在拿到的是一个完整的新工程。本次所有设置从零开始；不需要查找旧 GitHub 账号或旧签名。步骤按 Windows 电脑编写。

1. 先明确三个东西

名称 是什么 这次的做法
GitHub 账号 上传代码、运行构建所用的账号 使用一个你现在能登录并长期保管的账号；忘记旧账号不影响这个新工程
项目文件夹 同时能看到 app、tools、gradlew.bat、version.properties 的目录 解压交付包得到，不要再去找旧 TV 项目
签名密钥 证明后续 APK 和第一次安装属于同一个作者 在你电脑上新建一次，以后每次更新都用这一份

应用名字是 安华电视，版本 1.0，应用标识 cn.anhuatv.live.v1。新签名通常不能覆盖旧签名的应用；本工程按一个新的独立应用安装。即使电视上已有旧版，也不要把它当作这次的覆盖更新目标。

2. 准备账号和两个工具

  1. 打开 GitHub，登录你这次准备使用的账号；需要新账号时先注册并完成邮箱验证。
  2. 在密码管理器记录用户名、绑定邮箱和登录方式，保存账号恢复资料。
  3. 安装 GitHub Desktop，打开后用同一个账号登录。
  4. 安装 Temurin JDK 17。选 Windows / x64 / JDK / 17 / MSI。安装选项若提供 Set JAVA_HOME 和添加到 PATH，一并启用。安装后重新打开终端。

电脑不必安装 Android Studio。JDK 在这里主要用于生成新签名，Android 编译在 GitHub 上进行。

3. 解压并识别项目路径

先解压，不要在压缩包预览窗口里直接运行脚本。打开解压后的 anhua-tv-1.0 文件夹，你应能看到：

文件 / 文件夹 用途
.github/workflows GitHub 自动构建与发布配置，上传时必须保留
app Android 应用源码
gradle、gradlew、gradlew.bat Gradle 构建入口
tools 新签名及发布脚本
docs、先读我.html 操作与技术说明
version.properties 当前版本号

**这一级文件夹就是项目路径。**在资源管理器地址栏点击空白处，整行地址就是路径；不需要从系统中搜索旧项目。

如果在这个文件夹的地址栏输入 powershell 并按回车，就会打开当前目录的 PowerShell。运行：

Get-Location
Test-Path .\tools\New-SigningKey.ps1

第二条应该返回 True。若是 False，说明当前层级不对；退回资源管理器，进入能直接看到 tools 和 app 的那一级。

4. 用 GitHub Desktop 创建并上传新仓库

建议仓库名称用 TV-Live，与旧项目区分。

  1. GitHub Desktop → File → New repository。
  2. Name 填 TV-Live；Local path 选你容易找的位置，例如 C:\Projects。此时新仓库路径为 C:\Projects\TV-Live。
  3. 创建仓库。若 Desktop 让你填写提交者姓名和邮箱，按你新账号填写。
  4. 在 Desktop 中点 Repository → Show in Explorer 打开新仓库目录。
  5. 把解压工程里面的全部文件与文件夹复制到新仓库目录。不是再套一层 anhua-tv-1.0；进入新仓库根目录应能直接看到 app、tools、.github、gradlew.bat。
  6. 如提示同名 README 等文件，保留本交付工程的文件。不要复制生成签名后的私人备份目录。
  7. 回到 Desktop，在左下 Summary 填 Initial AnhuaTV 1.0，点击 Commit to main（你当前默认分支若名称不同，以实际显示为准）。
  8. 点击 Publish repository。取消勾选 Keep this code private，使用 Public 公开仓库，然后发布。
  9. 点 View on GitHub。仓库首页应直接显示 app、tools、.github、version.properties。进入 .github/workflows 应能看到两份 .yml 文件。

这个工程的电视端更新通过公开 Releases 下载。私人仓库需要额外认证方案，本工程不会把 GitHub 密码或令牌放进电视 App，因此本教程采用公开仓库。代码可以公开，签名密钥和密码必须只放 Repository Secrets / 你自己的备份中。

不需要建立 Personal Access Token，也不需要找旧教程里的 Repository permissions → Contents。工作流中的 permissions: contents: write 会为本次运行申请仓库自带 GITHUB_TOKEN 的发布权限。

5. 在电脑上生成一次新的签名

在你准备长期使用的新仓库根目录打开 PowerShell，先检查位置：

Get-Location
Test-Path .\tools\New-SigningKey.ps1

确认 True 后运行：

powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\New-SigningKey.ps1
  1. 脚本会让你输入一遍新签名密码，再输入第二遍确认。
  2. 密码至少 8 位，使用英文字母、数字和英文符号，不含空格。输入时不显示字符是正常现象。
  3. 这是新建的 App 签名密码，不是 GitHub 登录密码。记录在密码管理器中。
  4. 默认输出目录是 C:\Users\你的Windows用户名\AnhuaTV-signing-v1。PowerShell 会打印实际路径。它在工程目录之外。
  5. 里面会生成 anhua-tv-v1.p12、TV_KEYSTORE_BASE64.txt、TV_KEY_ALIAS.txt、BACKUP-README.txt。密码不会写进文件。

脚本发现输出目录已存在时会停止，防止误覆盖已生成的密钥。如果已经成功生成过，不要重新创建，直接使用这份备份继续下一步。若刚才确实失败且只有不完整文件，先将失败目录改名，再重新执行；保留可能已有的有效密钥。

这次为了减少混淆，采用 PKCS12，密钥库密码与私钥密码使用同一个密码。虽然 GitHub 中仍有两项名字，但填入相同值即可。

如提示找不到 keytool：先确认已安装 JDK；重新打开 PowerShell。也可以显式提供实际路径，例如：

powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\New-SigningKey.ps1 -KeytoolPath 'C:\Program Files\Eclipse Adoptium\你的JDK目录\bin\keytool.exe'

示例中的“你的JDK目录”必须替换成电脑上真实的目录，不能原样照抄。

6. 设置四项 Repository Secrets

在新仓库网页中进入：

Settings → Secrets and variables → Actions → Secrets → New repository secret。

依次添加四项，名称必须完全一致，不要把名称写进 Secret 内容里：

Name（名称） Secret（内容） 从哪里获得
TV_KEYSTORE_BASE64 TV_KEYSTORE_BASE64.txt 的完整一行内容 新签名输出目录中的文本文件，不能填文件路径
TV_STORE_PASSWORD 刚才新建的签名密码 你在脚本中输入的密码
TV_KEY_ALIAS anhua-tv-v1 也可复制 TV_KEY_ALIAS.txt 内容
TV_KEY_PASSWORD 与 TVSTOREPASSWORD 完全相同 本工程使用统一的签名密码

复制 Base64 内容时可在 PowerShell 使用：

Get-Content -Raw "$env:USERPROFILE\AnhuaTV-signing-v1\TV_KEYSTORE_BASE64.txt" | Set-Clipboard

然后到 TV_KEYSTORE_BASE64 的 Secret 输入框粘贴。这条命令不会把密钥内容打印到屏幕上。

添加后页面只显示四个名称，看不到已保存内容是正常的；需要更正时使用对应项的编辑按钮。不要把 .p12、Base64 文本或密码文件作为代码上传到仓库。

7. 首次构建 1.0

  1. 进入仓库网页的 Actions。
  2. 可能先看到一个 Code checks 自动运行。这是代码检查，不生成可安装 APK，也不要求签名。
  3. 左侧选择 Build signed TV APK。
  4. 点击右侧 Run workflow，选择已上传完整工程的默认分支。
  5. 保持 Publish to Releases and enable in-app updates 为勾选 / true。
  6. 点击绿色 Run workflow 启动。
  7. 等待这次运行变成绿色。首次下载依赖可能需要几分钟。
  8. 回到仓库 Code 页，进入 Releases，打开 安华电视 1.0 / v1.0。
  9. 在 Assets 下载 AnhuaTV-1.0.apk。不要下载 GitHub 自动生成的 Source code (zip) 当作安装包。

同一 Release 中还应有一个 update.json。这是电视 App 检查更新用的描述文件，由工作流自动生成，不需要你手工编辑。

也可以在 Actions 那次运行底部的 Artifacts 下载 AnhuaTV-1.0，解压后获得 APK 和描述文件。Artifacts 需要网页登录；电视内更新只使用公开 Releases。

如果 Run workflow 没有出现：检查 .github/workflows/release.yml 是否在仓库根目录下的正确位置，并且已提交到默认分支；如果压缩包被直接作为一个 .zip 文件上传，GitHub 不会自动解压为工程。

8. 在 TCL Q10M 首次安装

  1. 将 AnhuaTV-1.0.apk 复制到 U 盘，插入 TCL Q10M，使用电视的文件管理器找到文件。
  2. 若电视询问未知来源安装权限，为你当前使用的文件管理器允许安装。
  3. 进入系统安装界面，确认安装并打开 安华电视。
  4. 首次启动会下载默认启用的 best-fan 订阅。若拿不到列表，右键进入订阅管理检查地址与网络。
  5. 旧版同名图标可能仍在；首次验收请从刚安装的应用打开，或在工具 → 使用说明中确认版本 1.0 与新仓库名称。

TCL 系统版本不同，文件管理和安装权限入口可能不同。若系统直接拦截安装，应以电视实际提示定位系统设置；本工程不能代替系统安装授权。

9. 遥控器怎么用

场景 按键 效果
全屏播放 上 / 下 前 / 后一个频道
全屏播放 确定或左键 打开频道列表
全屏播放 按住上 / 下 进入列表后连续移动选中项
频道列表 按住上 / 下 连续滚动；松开停住；按确定后才播放选中频道
频道列表 左 / 右 全部、收藏、央视、卫视、成都、其他之间切换
全屏或列表 长按确定约 0.6 秒后松开 收藏 / 取消收藏当前或选中频道
全屏播放 右键或菜单键 打开线路、测速、订阅、更新等工具
全屏或列表 数字键 输入列表左侧编号，约 1.1 秒后跳台；编号随订阅更新可能改变

音量键由电视系统处理。程序退出或切到后台时停止播放，返回应用后重新连接，不会在后台继续直播。

10. 订阅与换源

内置五个约定的网络订阅，默认开关如下：

订阅 初始状态 地址
best-fan 开 https://raw.githubusercontent.com/best-fan/iptv-sources/master/cn_all.m3u8
CNTV-V6 关，候选 https://peterhchina.github.io/iptv/CNTV-V6.m3u
fanmingming IPv6 关，候选 https://live.fanmingming.cn/tv/m3u/ipv6.m3u
suxuang 移动 IPTV 关，候选 https://raw.githubusercontent.com/suxuang/myIPTV/main/移动IPTV.m3u
IPTV-org 中国 关，候选 https://iptv-org.github.io/iptv/countries/cn.m3u

另有一个内置 成都 CDTV-1 IPv6（未验证），也是关闭状态。它只是此前讨论的候选地址，不是已验证的看度官方接入。可以启用后在你家网络实测；不能播放就继续关闭。

右键 → 订阅管理 → 选订阅，可以启停、改名称/地址/优先级或删除。改动会触发刷新。最好先只开 best-fan，再逐个测试其他候选，避免把本地不可达的线路带回播放队列。

要在发布前改默认地址：编辑 app/src/main/assets/sources.json。其中 enabled 控制开关，priority 越小越优先。已经安装的应用会优先使用它自己保存过的配置；换默认配置后如需让老用户使用，仍需在 App 中修改相应订阅。

右键 → 当前频道线路 / 手动换源 可查看同频道全部线路及最近结果，选一条立即播放。如果失败，程序会继续尝试剩余线路；每次连接周期各线路最多尝试一次，全部失败后等待你重试或换台，避免无限循环。

原生切台速度取决于流服务器、关键帧间隔、网络和电视解码能力，不能保证固定秒数。播放器重用同一个 ExoPlayer，并使用较小起播缓冲，但不会用“URL 能访问”代替出画验收。

11. 两类测速有什么差别

工具 实际做什么 能得出什么结论
本地网络测速 本机 GET 直播地址；HLS 会跟进变体和媒体分片，抽样读取最多 64 KB 本机此时能取到一段数据及其耗时，不代表已经解码出画
逐路出画实测 用电视当前的原生播放器逐条打开线路，等待真实首帧事件，单条最多约 12 秒 该电视此时能够渲染视频首帧；不是长时间稳定性或音画同步的保证

逐路实测时临时静音，结束或停止后恢复原频道。测速会消耗少量网络流量。结果保存在本机，排序只参考最近 24 小时的结果；线路“最近失败”后也能手动重新验证。

12. 怎样发布 1.1 并在 App 内升级

以后只要保留同一个应用标识、同一份签名和同一个新仓库，就可以持续更新。

  1. 修改代码后，打开仓库根目录的 version.properties。
  2. 从首次的：
versionCode=1
versionName=1.0

改成：

versionCode=2
versionName=1.1
  1. 更新 release-notes.md，写这次变化。
  2. 使用 GitHub Desktop 提交更改，然后 Push origin。
  3. 在 Actions 手动运行 Build signed TV APK，保持发布选项开启。
  4. 工作流会先检查该标签是否已存在、versionCode 是否高于当前公开版本，通过后构建并完整发布 v1.1。
  5. 在电视打开安华电视 → 右键 → 检查应用更新 → 下载 → 确认安装。
  6. 第一次从 App 内安装时，系统可能要求允许“安华电视”安装未知来源应用；允许后返回，会继续打开安装界面。

这属于“在 App 内检查与下载，交给系统确认安装”，不是静默后台安装。电视无需每次再用 U 盘，但电视必须能访问 GitHub Releases。

签名丢失时无法用另一把随机密钥覆盖同一应用。请把 .p12 文件、Base64 副本、别名、密码、新仓库地址 做一次可靠备份；不要在每次发版时重新运行新签名脚本。

若某次构建通过但发布失败，Actions 的 Artifacts 里仍可下载成品；如果留下了 Draft Release，可以到 Releases 检查。重试前若使用相同版本，先核对该草稿的内容。这个工作流会拒绝覆盖已存在版本；最直观的修复是保留原版并递增 versionCode、versionName 后重新发布。

14. 首次电视验收

建议首次安装后按以下次序确认：

  1. 工具 → 使用说明显示 1.0 与你的新仓库。
  2. best-fan 载入后，至少各播一个央视和卫视频道，持续观察几分钟。
  3. 上下切台，确定开列表，长按上下移动后按确定，验证没有网页闪现。
  4. 长按确定收藏；重启 App 后检查收藏及上次成功播放频道。
  5. 在有多条线路的频道分别做网络抽样与逐路实播，手动选择一条线路。
  6. 临时启用一个其他订阅，确认刷新；停用后确认对应独有频道退出列表。
  7. 发布一个更高的测试版本，完成一次“App 检查 → 下载 → 系统确认安装”的完整升级。

成都台和回看不作为本次 B 方案已经可用的验收项。当前交付的编译与测试范围见 验证记录。
