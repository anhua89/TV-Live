# 简视 TV 1.3：修正看度首页、网页缩放与黑屏提示

适用于已经安装本次新工程 1.0、1.1 或 1.2 的电视。当前版本 **1.3 / versionCode 4**，应用标识继续为 `cn.anhuatv.live.v1`。沿用你现有的 **TV-Live** 仓库、四项 Secrets 和同一份签名，不要重新生成密钥。

## 针对三张图的修正

| 反馈 | 1.3 的处理 |
|---|---|
| 看度新闻网入口不对 | 默认改为你截图中的 `https://cditv.cn/` 首页；不再使用会进入历史新闻的 `/html/cdrtv/#live`。首页载入后尝试按实际 CDTV 标签定位电视直播区，不编造频道直达地址 |
| 电视页面和文字过大 | 默认请求桌面网页，保留电视真实的浏览器内核版本；文字缩放设为 100%，关闭文字自动放大，使用 1280 CSS 像素布局并按屏幕宽度适配。菜单仍可缩放、重新适配或切换兼容布局 |
| 点链接后只有黑屏 | 增加普通新窗口链接与脚本新窗口的当前窗口跳转；仅看度域名启用历史 HTTP 视频兼容；提供尝试播放、全屏与视频状态检测，明确区分无视频、未起播、媒体网络错误、解码/格式错误和不可读取的独立播放器 |

**第三项仍需电视验证。** 截图不能确定黑屏的唯一原因；开发环境访问看度首页仍返回 403，无法复现你电脑上能播放的直播。因此不能承诺已让所有 CDTV 链接出画。新版已修正入口和兼容逻辑，并加入可拍照反馈的网页诊断，避免只显示一块黑屏和“网页已加载”。

央视、四川卫视及其他非成都频道的原生播放器、订阅内容、线路排序、测速和收藏代码均保持原样。

## 更新工程并发布

1. 下载完整源码 ZIP，解压后进入 `jianshi-tv-1.3`。这一层直接能看到 `app`、`tools`、`.github`、`gradlew.bat` 和 `version.properties`。
2. 打开 GitHub Desktop，选 **TV-Live**，先点 **Fetch origin**；出现 **Pull origin** 时先拉取。
3. 点 **Repository → Show in Explorer** 打开当前仓库根目录。
4. 把 `jianshi-tv-1.3` **里面的所有文件和文件夹**复制进去，覆盖同名文件。不要再套一层项目文件夹，不要删除仓库自己的 `.git`。
5. Summary 填 `Fix Cditv home, desktop layout and web playback handling`，点 **Commit to main**，再点 **Push origin**。
6. 等最新提交的 **Code checks** 通过。现有工作流会额外自动运行网页适配的 JavaScript 逻辑检查，不用新增任何 Secrets。
7. GitHub → Actions → **Build signed TV APK → Run workflow**，保持正式发布选项开启。
8. 成功后 Releases 应有 **v1.3**，附件含 **JianshiTV-1.3.apk**、**update.json** 和频道目录。

这个源码 ZIP 不是安装包，也不会自行改变电视上的 App。若你的仓库已经发布过 v1.3，需同时递增 versionCode、versionName 再发布，不覆盖既有 Release。

## 在电视升级和检查

能访问 GitHub Releases：旧 App → 右键 → **检查应用更新** → 下载 → 系统确认安装。

更新连接超时：电脑从同一个 Release 下载 **JianshiTV-1.3.apk**，用 U 盘同签名覆盖安装，不必卸载。这样可保留收藏和配置。

安装后：

1. 工具 → 使用说明确认 **1.3**。
2. 先播放一个央视和四川卫视频道，确认仍为原生播放。
3. 打开成都网页，点顶部 **看度直播**，确认显示首页的电视直播区，而不是 2023 年的新闻文章。旧版保存的已知错误默认地址会自动迁移；个人填过的其他网址仍保留。
4. 如果没有自动滚到直播区，按 **菜单 → 定位电视直播区**，或用翻页键滚动。
5. 页面仍显得大时，按 **菜单 → 重新适配屏幕**；也可以用 **缩小网页**。如果网站桌面版不兼容，可试 **切换兼容布局**。
6. 用光标点击 CDTV 频道和网页播放按钮，也可点顶部 **播放 / 全屏 → 尝试播放**。
7. 检查画面、声音和几分钟的持续播放；“检测到视频进度推进”仍不等于这些项目都已通过。

## 如果仍然黑屏

先等待约 12 秒，查看顶部的提示，再按 **菜单 → 网页诊断**。可以拍下这一页反馈，无需连接电脑调试电视。

诊断页包含：实际页面地址和标题、布局宽度、可检测的视频数、独立播放器数、视频进度/帧数、媒体错误码、网络/脚本提示及真实浏览器版本。不显示网址查询参数中的令牌、密码或 Cookie。

| 提示 | 说明与下一步 |
|---|---|
| 当前页面未检测到视频 | 可能打开了其他内容，点“看度直播”回到首页，再选电视直播 |
| 视频尚未开始或等待数据 | 用光标点网页播放按钮，或使用“尝试播放”；随后查看诊断 |
| 媒体网络请求失败 | 页面已打开，但视频数据没能取到；截图诊断页中的网络提示 |
| 解码失败 / 格式或来源不支持 | 当前网页组件不能处理该媒体，试菜单里的电视浏览器 |
| 播放器位于独立网页 | 跨来源框架中的视频状态不能直接读取，不代表一定播放失败；用光标操作播放器或试电视浏览器 |
| 网页拒绝播放 / 全屏请求 | 用光标直接点网页内部的播放或全屏图标 |

**在电视浏览器打开**是可选的兼容方式，不能保证成功；若电视没有浏览器会提示并允许返回。返回键先退出视频全屏，再回到频道列表。

## 验证范围

- 53 项 Java、11 项 Python、12 项 JavaScript 逻辑回归测试通过，共 76 项。
- 所有应用 Java 源码及测试源码编译、Android 资源编译与链接通过。既有两份工作流和签名配置没有变化。
- JavaScript 测试使用受控 DOM 数据验证逻辑，不是电视浏览器渲染或真实直播测试。
- 没有生成 APK、代你运行 GitHub Actions、完成完整 Gradle/Lint 构建，也没有完成 TCL Q10M 网页缩放、成都台出画或覆盖安装的实机验收。
- 本版未增加 App 原生 EPG/回看播放器；网页是否提供回看由网站决定。
