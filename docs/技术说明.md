# 简视 TV 1.2 技术说明

## 工程与数据

这是一个从零编写的 Java Android 应用。央视、卫视及其他非成都频道采用 Android 原生 View / ListView 和 Media3。1.2 按用户要求，仅为成都频道增加独立 WebView Activity。applicationId 为 `cn.anhuatv.live.v1`；`namespace` 为 `cn.anhuatv.live`。两者可以不同，Manifest 与 FileProvider 使用实际 applicationId。

| 文件 | 职责 |
|---|---|
| `MainActivity.java` | 原生电视界面、遥控器、频道分组/收藏、订阅管理、导入、测速界面与生命周期 |
| `LivePlayer.java` | ExoPlayer 复用、请求头、线路切换、首帧与缓冲看门狗、逐路实播 |
| `WebChannelActivity.java` | 成都网页、遥控器光标/点击、全屏、网址编辑、外部浏览器与返回列表 |
| `core/WebChannelRoutes.java` | 严格识别成都频道、补充独立网页入口、验证网页 URL |
| `ChannelRepository.java` | 并发订阅读取、缓存、离线回退、本地导入列表读取 |
| `Store.java` | 私有配置、上次频道、收藏、偏好线路和本机健康记录 |
| `Net.java` | 有限大小的网络读取、重定向、媒体抽样；不把探测伪装成解码测试 |
| `UpdateManager.java` | 新仓库的 Release 描述、下载校验、签名对比与系统安装 |
| `core/PlaylistParser.java` | 纯 Java 的 Extended M3U/TXT、IPv6、常见请求头和 catchup 元数据解析 |
| `core/Catalog.java` | 名称归一、线路去重、分组与排序 |
| `core/CatalogResolver.java` | 验证并选择网络、缓存与内置目录；首次启动无需访问远程目录 |
| `core/RouteOrder.java` | 上次成功线路、实播结果、网络抽样、来源优先级及健康记录有效期 |

Manifest 支持电视 Launcher、横屏、无触屏设备和硬件加速。为常见明文直播流允许 HTTP；更新描述与 APK 强制 HTTPS，不允许 HTTPS 重定向降级到 HTTP。

## 数据保存与导入

- 订阅原文缓存在应用私有 `files/lists`，本地导入保存在 `files/imports`。
- 收藏、上次成功频道和来源配置保存在私有 SharedPreferences。
- 初始列表先读缓存或内置 best-fan，再后台刷新。各来源最多三路并发；单次整批刷新有时限，失败保留可用缓存。
- 下载列表最大 8 MiB，单来源最多解析 20,000 条。不是把整个互联网上的直播目录无限拉入内存。
- 本地导入使用系统 Storage Access Framework，不申请宽泛的存储访问权限。部分电视没有可用文档选择器，会提示改用网络订阅。
- 修改来源后重新合并启用的列表。归一名称是频道标识；CCTV-5 与 CCTV-5+、4K 与普通频道、CCTV4 地区版分别处理。
- 相同地址但请求头不同的线路保留；相同地址与相同请求头去重，优先较小的来源 `priority`。未知频道不会只因复用了 `tvg-id` 而强行合并。

## 遥控器与播放

频道列表由 Android ListView 承载。按住方向键只改变选中位置，节流约 75 ms；松开停住，确定键抬起后提交播放。全屏长按上下会进入列表，因此不会持续对几十个频道发起网络连接。列表左右切换类别，右键工具在全屏场景打开。

播放器复用一个 ExoPlayer，启用设备解码回退；视频输出为 SurfaceView。初始起播缓冲约 300 ms、重缓冲约 900 ms，目标缓冲约 1.8–9 秒；它们是缓冲配置，不是承诺的实际切台耗时。网络、关键帧和设备解码能力会影响首帧。

每次播放连接有有限的候选队列，依次尝试且避免同一轮无限重试。触发下一条的条件包括：

| 条件 | 阈值 / 行为 |
|---|---|
| 播放器错误或直播结束 | 立即尝试剩余线路 |
| 尚未渲染视频首帧 | 最长约 12 秒 |
| 持续缓冲 | 最长约 10 秒 |
| 播放处于 READY 且进行中，但进度停止 | 约 15 秒 |
| 所有线路失败 | 停止循环，提示手动重连、测速或换台 |

仅有声音而没有视频首帧也不会被记为“已出画”。进入后台时停止；回前台按上次成功频道重连。播放器、线程和 Handler 在 Activity 销毁时释放。

## 本机测试与排序

“网络抽样”会 GET 数据而不是只做 HEAD；HLS 最多跟进若干层清单，再读取最多 64 KiB 媒体抽样，识别明显 HTML 错误页。这个结果只代表数据抽样可达，不能证明视频有效、解密成功、节目正确或设备支持该编码。RTSP 与需要额外解析的 DASH 应使用实际出画测试。

“出画实测”使用电视当前播放器，逐条等待 `AnalyticsListener.onRenderedFirstFrame`。事件中的 mediaId 与本轮线路匹配才记录成功；每条有时限。期间静音，结束/取消后恢复频道。首帧成功仍不等于持续稳定或音画同步达标。

排序参考最近 24 小时的数据。最近失败降低优先级；有效偏好线路优先，其次已有实际首帧的线路、网络抽样通过的线路、未测线路。相同层级参考来源优先级，随后参考耗时。所有结果只保存在这台设备上。

## 更新链路

1. Actions 构建时自动使用 `GITHUB_REPOSITORY` 写入新仓库地址；没有旧账号硬编码。
2. 电视访问 `https://github.com/用户名/仓库名/releases/latest/download/update.json`。客户端不使用 GitHub API，也不携带令牌。
3. 仅接受更高版本，检查目标应用标识、最小系统版本、大小限制、SHA-256 格式和属于当前仓库的 Release 地址。
4. 通过 HTTPS 下载到私有缓存；核对准确字节数、SHA-256、安装包包名、版本号、与已安装 App 相同的当前签名集合。
5. 使用限制到更新目录的 FileProvider 交给系统安装。Android 8+ 需要本 App 获准安装未知来源应用；用户在系统界面完成确认。

新密钥脚本只在用户电脑生成 PKCS12。密钥库与私钥密码保持一致；脚本不保存密码，不回显 Base64。GitHub 中的签名材料来自四项 Secrets。正式工作流不会退回调试签名，配置缺失时直接失败。

正式构建会先刷新内置 best-fan；网络失败时保留验证通过的现有目录。Release 附带 channels.m3u，供电视在原始订阅不可达时尝试和用户手动导入。发布时先生成 APK、描述与目录，再建立 Draft Release，全部附件准备齐后发布并设为 Latest。重复标签或没有递增的 `versionCode` 会被拒绝，避免旧版更新信息被覆盖。本代码未实现签名轮换；持续更新应保留同一份签名。

## 成都网页与回看

1.2 只将 CDTV-1～8 的频道标识、明确的成都电视台别名和内置成都网页入口交给 WebChannelActivity。四川卫视、央视和其他频道仍交给原有 LivePlayer。没有按“成都”分组整体拦截，也没有修改媒体地址、订阅和线路排序。若目录不含成都台，会补充“成都电视台（网页）”入口；若已有成都频道，保留其标识、收藏和原线路数据。原 CDTV-1 IPv6 候选订阅仍默认关闭，但即使启用该入口也按网页方式打开。

默认共享网址为 `https://www.cditv.cn/html/cdrtv/#live`。这是需在页面内选台的入口，不宣称直达所点击的某一套；具体网址尚未获用户确认。2026-10-15 开发环境访问此页面返回 HTTP 403，未能验证当前播放能力。未使用官网旧版导航中已失效的 gblock 逐频道地址，也没有编造 CDTV 媒体流或动态签名参数。网页地址可在电视菜单中修改，保存后影响成都频道，不影响任何网络订阅。

进入网页前挂起原生播放器，返回后回到频道列表并恢复此前的原生频道。成都网页不会写入原生播放成功记录或触发原生线路实测。页面载入完成只显示“网页已加载”，不会记为视频已出画。

WebView 启用 JavaScript、DOM storage、HTML5 视频和 WebChromeClient 全屏回调。遥控器方向键移动可见光标，确定键模拟点击；频道加减/翻页键滚动网页；菜单可刷新、缩放、编辑地址或选择外部浏览器。返回键先退出网页视频全屏，再返回原生频道列表。网页退到后台先暂停媒体并卸载当前页面，回前台重新加载，以免网页声音和其他播放器叠加。

网页只接受无内嵌账号密码的 HTTP/HTTPS 地址，关闭文件/content 访问，不注入原生 JavaScript 接口，不忽略证书错误。使用 mixed content compatibility 模式以兼容部分历史页面，不降低应用更新的 HTTPS 限制。网页组件缺失或浏览器不可用会给出可返回的提示。打开网页不等于成功直播；网站限制和电视浏览器兼容性必须实机检查。

回看的元数据已解析并随线路保存；没有 EPG 下载、时区/日期选单、catchup URL 时间参数替换或回看状态机。因此不展示可用回看按钮。后续应先确认稳定、获准使用的来源，再增加 EPG 和回看控制；不能只在普通直播地址后随意拼时间参数。
