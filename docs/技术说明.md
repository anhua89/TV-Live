# 简视 TV 1.5 技术说明

## 工程与数据

这是一个从零编写的 Java Android 应用。原有直播频道采用 Android 原生 View / ListView 和 Media3。1.2 为成都频道增加独立 WebView Activity；1.4 增加咪咕、优酷两个独立网页频道；1.5 为这两个站点加入专用适配与恢复逻辑，沿用该 Activity。applicationId 为 `cn.anhuatv.live.v1`；`namespace` 为 `cn.anhuatv.live`。两者可以不同，Manifest 与 FileProvider 使用实际 applicationId。

| 文件 | 职责 |
|---|---|
| `MainActivity.java` | 原生电视界面、遥控器、频道分组/收藏、订阅管理、导入、测速界面与生命周期 |
| `LivePlayer.java` | ExoPlayer 复用、请求头、线路切换、首帧与缓冲看门狗、逐路实播 |
| `WebChannelActivity.java` | 成都、咪咕与优酷网页；遥控器光标/点击、全屏、各自网址/布局、外部浏览器与返回列表 |
| `core/WebChannelRoutes.java` | 识别成都别名与两个保留入口 ID，补充三个网站入口、验证网页 URL |
| `core/VideoSitePolicy.java` | 咪咕独立桌面宽度、官方手机/桌面节目路径、真实 UA 与受保护媒体来源限制 |
| `assets/video_sites_tv.js` | 咪咕/优酷轻量布局、数量受限的视频状态读取、现有控制条操作与全屏 |
| `core/WebPagePolicy.java` | 旧默认网址迁移、官方域名边界、桌面 UA、诊断 URL 去除查询参数 |
| `core/ChannelSelection.java` | 频道列表上下首尾循环；空列表与未选中位置处理 |
| `assets/cdtv_tv.js` | 电视 viewport、直播区定位、播放/全屏操作及不把页面加载当作视频播放的状态观察 |
| `ChannelRepository.java` | 并发订阅读取、缓存、离线回退、本地导入列表读取 |
| `Store.java` | 私有配置、上次频道、收藏、偏好线路和本机健康记录 |
| `Net.java` | 有限大小的网络读取、重定向、媒体抽样；不把探测伪装成解码测试 |
| `UpdateManager.java` | 新仓库的 Release 描述、下载校验、签名对比与系统安装 |
| `core/PlaylistParser.java` | 纯 Java 的 Extended M3U/TXT、IPv6、常见请求头和 catchup 元数据解析 |
| `core/Catalog.java` | 名称归一、线路去重、分组与排序 |
| `core/CatalogResolver.java` | 验证并选择网络、缓存与内置目录；首次启动无需访问远程目录 |
| `core/RouteOrder.java` | 上次成功线路、实播结果、网络抽样、来源优先级及健康记录有效期 |

Manifest 支持电视 Launcher、横屏、无触屏设备和硬件加速。为常见明文直播流允许 HTTP；更新描述与 APK 强制 HTTPS，不允许 HTTPS 重定向降级到 HTTP。

## 数据保存与导入

- 订阅原文缓存在应用私有 `files/lists`，本地导入保存在 `files/imports`。
- 收藏、上次成功频道和来源配置保存在私有 SharedPreferences。
- 初始列表先读缓存或内置 best-fan，再后台刷新。各来源最多三路并发；单次整批刷新有时限，失败保留可用缓存。
- 下载列表最大 8 MiB，单来源最多解析 20,000 条。不是把整个互联网上的直播目录无限拉入内存。
- 本地导入使用系统 Storage Access Framework，不申请宽泛的存储访问权限。部分电视没有可用文档选择器，会提示改用网络订阅。
- 修改来源后重新合并启用的列表。归一名称是频道标识；CCTV-5 与 CCTV-5+、4K 与普通频道、CCTV4 地区版分别处理。
- 相同地址但请求头不同的线路保留；相同地址与相同请求头去重，优先较小的来源 `priority`。未知频道不会只因复用了 `tvg-id` 而强行合并。

## 遥控器与播放

频道列表由 Android ListView 承载。上下按键按当前可见分组的数量循环：首项向上到末项，末项向下到首项；空分组不选中，单项分组仍选中自身。按住方向键只改变选中位置，节流约 75 ms；松开停住，确定键抬起后提交播放。全屏长按上下会进入列表，因此不会持续对几十个频道发起网络连接。列表左右切换类别，右键工具在全屏场景打开。

播放器复用一个 ExoPlayer，启用设备解码回退；视频输出为 SurfaceView。初始起播缓冲约 300 ms、重缓冲约 900 ms，目标缓冲约 1.8–9 秒；它们是缓冲配置，不是承诺的实际切台耗时。网络、关键帧和设备解码能力会影响首帧。

每次播放连接有有限的候选队列，依次尝试且避免同一轮无限重试。触发下一条的条件包括：

| 条件 | 阈值 / 行为 |
|---|---|
| 播放器错误或直播结束 | 立即尝试剩余线路 |
| 尚未渲染视频首帧 | 最长约 12 秒 |
| 持续缓冲 | 最长约 10 秒 |
| 播放处于 READY 且进行中，但进度停止 | 约 15 秒 |
| 所有线路失败 | 停止循环，提示手动重连、测速或换台 |

仅有声音而没有视频首帧也不会被记为“已出画”。进入后台时停止；回前台按上次成功频道重连。播放器、线程和 Handler 在 Activity 销毁时释放。

## 本机测试与排序

“网络抽样”会 GET 数据而不是只做 HEAD；HLS 最多跟进若干层清单，再读取最多 64 KiB 媒体抽样，识别明显 HTML 错误页。这个结果只代表数据抽样可达，不能证明视频有效、解密成功、节目正确或设备支持该编码。RTSP 与需要额外解析的 DASH 应使用实际出画测试。

“出画实测”使用电视当前播放器，逐条等待 `AnalyticsListener.onRenderedFirstFrame`。事件中的 mediaId 与本轮线路匹配才记录成功；每条有时限。期间静音，结束/取消后恢复频道。首帧成功仍不等于持续稳定或音画同步达标。

排序参考最近 24 小时的数据。最近失败降低优先级；有效偏好线路优先，其次已有实际首帧的线路、网络抽样通过的线路、未测线路。相同层级参考来源优先级，随后参考耗时。所有结果只保存在这台设备上。

## 更新链路

1. Actions 构建时自动使用 `GITHUB_REPOSITORY` 写入新仓库地址；没有旧账号硬编码。
2. 电视访问 `https://github.com/用户名/仓库名/releases/latest/download/update.json`。客户端不使用 GitHub API，也不携带令牌。
3. 仅接受更高版本，检查目标应用标识、最小系统版本、大小限制、SHA-256 格式和属于当前仓库的 Release 地址。
4. 通过 HTTPS 下载到私有缓存；核对准确字节数、SHA-256、安装包包名、版本号、与已安装 App 相同的当前签名集合。
5. 使用限制到更新目录的 FileProvider 交给系统安装。Android 8+ 需要本 App 获准安装未知来源应用；用户在系统界面完成确认。

新密钥脚本只在用户电脑生成 PKCS12。密钥库与私钥密码保持一致；脚本不保存密码，不回显 Base64。GitHub 中的签名材料来自四项 Secrets。正式工作流不会退回调试签名，配置缺失时直接失败。

正式构建会先刷新内置 best-fan；网络失败时保留验证通过的现有目录。Release 附带 channels.m3u，供电视在原始订阅不可达时尝试和用户手动导入。发布时先生成 APK、描述与目录，再建立 Draft Release，全部附件准备齐后发布并设为 Latest。重复标签或没有递增的 `versionCode` 会被拒绝，避免旧版更新信息被覆盖。本代码未实现签名轮换；持续更新应保留同一份签名。

## 网页频道与回看

1.2 只将 CDTV-1～8 的频道标识、明确的成都电视台别名和内置成都网页入口交给 WebChannelActivity。四川卫视、央视和其他频道仍交给原有 LivePlayer。没有按“成都”分组整体拦截，也没有修改媒体地址、订阅和线路排序。若目录不含成都台，会补充“成都电视台（网页）”入口；若已有成都频道，保留其标识、收藏和原线路数据。原 CDTV-1 IPv6 候选订阅仍默认关闭，但即使启用该入口也按网页方式打开。

1.3 将默认网址改为用户电脑截图中的 `https://cditv.cn/` 首页。原 `/html/cdrtv/#live` 在用户电视上进入了 2023 年新闻文章，不能继续作为默认直播入口。升级时只迁移匹配已知旧路径、无自定义查询参数的保存值；保留其他自定义网址。首页直播区通过实际 CDTV 标签查找并定位，不猜测站点 CSS 选择器、频道 URL 或直播媒体地址。

1.4 的 `MIGU_WEB` 与 `YOUKU_WEB` 是两个明确保留的入口 ID，默认分别打开 `https://www.miguvideo.com/` 与 `https://www.youku.com/ku/webhome`。补充入口追加在“全部”末尾，归入“其他”，不改变原生频道顺序；重复刷新不重复添加。只有这两个 ID 才转到对应网页，不按名称中的“咪咕”“优酷”拦截原生订阅。没有订阅或订阅全部失败时，三个网站入口仍保留。

Activity 根据白名单 `site_key` 选择站点。成都继续使用原有 `page_url` / `desktop_mode` 配置键，新站点分别使用带 `_migu` / `_youku` 后缀的键；网址与布局互不覆盖。只有成都首页自动定位 CDTV 电视直播区，咪咕/优酷从首页选择节目，菜单提供“返回页面顶部”。

默认桌面模式保留电视实际 Chromium 版本，移除 Android/Mobile/wv 标识；文字缩放 100%，NORMAL 布局，成都/优酷桌面设置 1280 CSS 像素 viewport（咪咕在 1.5 单独使用 1920），并以 WebView 实际物理宽度设置初始比例。菜单提供重新适配、缩放和兼容布局。没有把电视分辨率简单当作网页 CSS 宽度。

普通 target=_blank 链接在当前页打开。脚本新窗口只接受用户手势，通过 WebViewTransport 临时 WebView 获取真实 HTTP/HTTPS 目标后回到主窗口；自动弹窗与外部 App scheme 不会自动打开。弹窗只处理一次并有超时清理，离开前台/页面代次变化后不能再跳转旧链接。第三方 Cookie 支持限定在看度域名或当前站点的官方域名；历史 HTTP 媒体兼容仍仅限看度域名。域名匹配使用完整主机名/子域边界。没有忽略证书错误，没有引入原生 JavaScript bridge；应用代码不提取或复制 Cookie 内容，登录由网站与 WebView 自行处理。

成都继续使用 cdtv_tv.js 观察顶层及可访问的同源 iframe 中的视频。只有视频进度或视频帧实际增加，才显示“检测到进度推进”；暂停、进度不变、没有视频、隐藏的预加载视频和无法访问的跨源 iframe 都不当作成功。检测到媒体错误会显示网络/解码/格式等类别，约 12 秒仍没开始会提供播放与诊断入口。跨来源 iframe 的内部状态无法读取时如实标注，不能由此认定它一定播放失败。进度推进也不代表内容正确、实际可见画面、声音与长期稳定性均已通过。

网页诊断提供地址/标题、viewport 宽度、视频与 iframe 数量、媒体错误码、进度/帧数、请求/脚本提示和真实浏览器 UA。页面地址与失败资源地址均去掉 query 和 fragment，不保存凭证。诊断只在本机显示，不上传。JSON 状态由 evaluateJavascript 回调读取，不向网页暴露原生接口。

进入网页前挂起原生播放器，返回后回到频道列表并恢复此前的原生频道。网页退到后台暂停媒体并卸载页面，回前台重新加载；状态轮询、弹窗和过期回调按前台状态和页面代次停止。三个网页频道都不写入原生线路的首帧成功记录。更新包的 HTTPS/大小/SHA/包名/版本/签名校验不变。

用户已反馈 1.3 成都网页可用，本版保留其适配脚本、首页与操作逻辑。咪咕/优酷默认地址依据用户截图中的官方域名；1.5 已读取官方桌面与手机页面 HTML，并核对已公布的对应节目路径。这些信息不等于新增站点已经在 TCL Q10M 实播。JavaScript 回归使用受控 DOM 数据，验证的是逻辑，不是电视 WebView 或网络直播；网站登录、会员权益、设备兼容性与节目限制由网站决定。

### 1.5 咪咕/优酷专用适配与恢复

咪咕采用 1920 CSS 像素桌面宽度；在加载进度达到 40% 后启动轻量适配，修改 viewport 时通知网站 resize，并在首轮布局就绪后校正一次实际缩放。其后不持续强制重置用户手动缩放。优酷桌面宽度保持 1280，成都保留原脚本与布局。

video_sites_tv.js 最多检查 4 个直接 iframe 和 8 个视频元素，避免在复杂网站中反复扫描大量节点。只保留一个未返回的 evaluateJavascript 请求；Handler 在回调外每约 1.8 秒继续计时，超过 8 秒仍未返回时显示无响应提示。仅明确的播放页在约 25 秒仍未就绪时提示恢复，首页没有视频不视为播放失败。此机制不能解决系统主线程或整机本身失去响应。

API 26+ 的 onRenderProcessGone 会移除并销毁失效 WebView，保留原生页面和修复菜单。API 29+ 注册 WebViewRenderProcessClient 观察无响应；用户选择重新打开时，必要时终止已被系统标记无响应的网页进程，再创建新 WebView。旧页面回调按 WebView 对象及页面代次检查，不能覆盖新页面。退出后台时停止轮询与待处理权限。

网页工具的第一项为“播放修复”，由原生 AlertDialog 提供，不依赖网页脚本。重新打开会重建 WebView，保留 Cookie；切换网页版本使用当前节目地址和真实 Chromium 版本。咪咕 detail/vertical/live、优酷 v_show/video 的映射依据官网规则和 alternate 元数据，保留节目 ID、原始 query 和 fragment；未知路径不改写。服务器重定向放行，只在用户点击已知播放链接时按手机模式转换，避免主站与手机首页互相重定向。手机网页仍可能触发网站验证或 App 引导。

遥控光标在这两个站点向 WebView 发送鼠标悬停事件；用户选择尝试播放时，只对实际存在的视频启用 controls 并调用 play，不能创建缺失的网站播放器。新版诊断增加媒体源是否存在、networkState、视频尺寸、MediaSource 能力和脚本等待时间，不暴露媒体 URL。

如果官方当前 HTTPS 来源请求 RESOURCE_PROTECTED_MEDIA_ID，显示原生确认框；仅在用户同意、来源主机与当前主页面一致且端口为 443 时授予这一项。其他资源（包括摄像头、麦克风）不授予，未知站点不接受。授权仅用于网站正常申请许可，不代替网站账户、权益或设备校验；本次没有验证两个站点是否实际发起此请求。

实现依据：[WebView 缩放](https://developer.android.com/reference/android/webkit/WebView#setInitialScale(int))、[网页进程响应](https://developer.android.com/reference/android/webkit/WebViewRenderProcessClient)、[网页权限](https://developer.android.com/reference/android/webkit/PermissionRequest)。官网路径核对页：[咪咕播放页](https://www.miguvideo.com/p/detail/953150738)、[截图中的优酷播放页](https://v.youku.com/v_show/id_XNjUzMDk4NjM5Mg==.html)。只核对页面和路径，未使用接口提取直播地址或复用浏览器凭证。

回看的元数据已解析并随线路保存；没有 EPG 下载、时区/日期选单、catchup URL 时间参数替换或回看状态机。因此不展示可用回看按钮。后续应先确认稳定、获准使用的来源，再增加 EPG 和回看控制；不能只在普通直播地址后随意拼时间参数。
