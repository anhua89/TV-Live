# 2026-10-15：Android SDK 初始化步骤修正

适用截图：`Code checks` 在 `Run android-actions/setup-android@v3` 失败，后面的 Gradle、SDK 安装和源码检查尚未开始。

截图只有调用堆栈末尾，不能据此断言底层原因。本次调整去掉失败的初始化 Action，使用 GitHub Ubuntu 24.04 运行器预装的 SDK。应用版本仍为 1.0，不需要重建仓库或重新生成签名。

## 已调整

- 两份工作流从 `ubuntu-latest` 固定为 `ubuntu-24.04`。
- 移除 `android-actions/setup-android@v3`。
- 检查预装的 Android 35、Build Tools 35.0.0 和 apksigner，向环境及本地 Gradle 配置写入实际 SDK 路径。
- 已存在所需组件时，不调用 sdkmanager，不重新下载命令行工具。
- 只有所需组件缺失时，才用运行器现有 sdkmanager 接受许可并补齐指定组件；使用文件输入，避免 `yes | sdkmanager` 管道的提前退出问题。

## 你要做的操作

1. 重新下载完整交付包并解压。
2. 只把 `.github/workflows/check.yml` 和 `.github/workflows/release.yml` 两份文件覆盖到你当前仓库的相同位置。
3. GitHub Desktop 中检查变更，填写 `Fix Android SDK setup`，Commit，再 Push origin。
4. 等待新提交触发的 `Code checks`。查看的是最新提交对应的运行，不要直接重跑旧的失败记录。
5. 检查通过且签名 Secrets 已配齐后，在 Actions → Build signed TV APK → Run workflow 发起正式构建。

如果只用 GitHub 网页：进入仓库 `.github/workflows/check.yml`，点击编辑，把文件内容完整替换成修正版并 Commit；再同样更新 `release.yml`。最后从默认分支发起新的工作流运行。

本次只调整构建环境。已有四项 Secrets、签名文件、应用标识和版本号均可沿用。

## 验证及后续定位

两份工作流通过 actionlint 静态检查。环境脚本在本地模拟“SDK 已预装”和“组件需要补齐”两条分支通过；这些检查不能替代你仓库上真正的 GitHub Actions 运行。

如果最新运行仍失败，请打开那个红色步骤，提供最前面的 `Error:` / `Exception:` / `Failed` 及其前后约 20 行文字。调用堆栈的最后几行通常没有完整原因。

## 后续：Android Lint 的 API 兼容性修正

新截图已进入 `Check source, tests and lint`，显示 `NewApi` 检查说明。截图未包含首条具体错误，不能断言全部失败项。

核对原工程发现：`app/src/main/res/values/styles.xml` 中设置了 `android:windowLightStatusBar`，该属性始于 API 23，而项目 minSdk 为 21。它应受资源版本限定，或在不需要时移除。本版全屏电视界面不需要显式设置该属性，已删除这一行：

```xml
<item name="android:windowLightStatusBar">false</item>
```

若你的两份工作流已经替换，这次只需同步 `app/src/main/res/values/styles.xml`，然后 Commit、Push。也可直接在 GitHub 仓库页面编辑这个文件，删除这一行后提交。

本次未关闭 NewApi 检查、未提高 minSdk。修正后资源重新编译与链接通过；按 Android SDK 的 API 元数据检查通用资源中的 Android 属性也通过。实际 `lintDebug` 结果仍需由最新 GitHub 运行确认。若还有错误，提供首条 `Error:` 所在段落或上传 Actions 的 `check-reports` 报告。
