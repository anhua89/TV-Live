# 简视 TV 1.1：修复“0 个频道”并更名

适用情况：已经安装 1.0，电视提示连接 `raw.githubusercontent.com:443` 约 7000 ms 后超时，随后显示 0 个频道。

这是频道目录未能下载的错误。它尚未证明目录里的节目流都不可播，也不能由这张图推断一定是 DNS 出错。截图已经显示域名解析出了 IP，超时发生在后续连接阶段。

## 可以先导入列表验证

本次另附 `best-fan-20261015.m3u`，保留 best-fan 当前列表内容，不修改直播地址。当前包含 186 条线路地址，并不等于 186 个不同频道或 186 条已验证可播放线路。

1. 在电脑下载这个 M3U 文件，复制到 U 盘。
2. 将 U 盘插入 TCL Q10M。
3. 打开当前 App → 右键 → **导入本地 M3U / TXT**，选择 U 盘上的文件。
4. 目录出现后，选择央视或卫视频道，使用 **逐路出画实测** 验证电视上的播放能力。

若电视没有系统文件选择器，当前 App 会给出提示。可以直接按下面步骤构建安装 1.1，它已经内置该目录，不需要文件选择器。

## 1.1 改动

| 情况 | 处理 |
|---|---|
| 首次启动，没有任何缓存 | 直接读取 APK 内的 best-fan 目录，随后后台刷新 |
| 之前已有成功缓存 | 先显示缓存，再后台刷新 |
| 原始订阅可访问 | 使用验证通过的新目录并保存缓存 |
| 原始订阅超时 | 若已绑定仓库，尝试 Releases 的 channels.m3u；仍失败则保留缓存或内置目录 |
| 订阅返回错误 HTML 或空内容 | 不用它替换可用目录 |
| 手动停用 best-fan | 按你的开关设置排除它，不强行恢复 |
| 手动改了 best-fan 的 URL | 尊重自定义订阅，不自动混入默认内置列表 |

软件显示名称改为 **简视 TV**；应用标识继续为 `cn.anhuatv.live.v1`。版本已改为 **1.1 / versionCode 2**。

内置目录会随网络地址变化而过时，所以仍保留在线刷新、本地导入和自定义订阅。GitHub Releases 地址只是另一个可尝试入口，不承诺电视一定能连通 GitHub。

## 覆盖现有仓库并构建

本次修改了应用代码、资源、版本和正式发布流程，**需要同步整个工程内容**。

1. 下载新版完整代码 ZIP，解压，进入其中的 `jianshi-tv-1.1` 文件夹。该层应能直接看到 `app`、`tools`、`.github`、`gradlew.bat` 和 `version.properties`。
2. 打开 GitHub Desktop，选择现有 **TV-Live** 仓库，先点 **Fetch origin**；若出现 **Pull origin**，先完成拉取，包含你此前在网页上的修改。
3. 点 **Repository → Show in Explorer**，打开你正在维护的本地仓库根目录。
4. 把新版工程文件夹**里面的所有内容**复制过去，覆盖同名文件。不要再套一层 `jianshi-tv-1.1`，也不要删除仓库自身的 `.git` 目录。
5. 当前四项 Secrets、签名密钥和 GitHub 仓库均继续使用；私人签名备份仍放在代码目录之外。
6. 在 Desktop 的 Summary 填 `Fix first-start catalog and rename app`，点击 **Commit to main**，再点 **Push origin**。
7. 等待最新提交的 **Code checks**。
8. 检查通过后进入 Actions → **Build signed TV APK → Run workflow**，保持发布选项开启。
9. 成功后在 Releases 下载 **JianshiTV-1.1.apk**。

如果你的仓库已经使用过 v1.1，发布检查会拒绝同名标签。此时需要递增 versionCode、versionName，再发布新版本；不要覆盖已发布版本。

## 安装与确认

考虑到电视当前访问 GitHub 存在超时，建议这一次在电脑下载 APK，再用 U 盘覆盖安装，保留原 App 的数据。**使用同一份签名，不要重新生成密钥。**

安装后：

1. 工具 → 使用说明显示 **简视 TV 1.1**。
2. 启动时先出现目录，不再必须等待 Raw 下载完成。
3. 网络刷新失败时，目录仍保留；状态中可看到使用缓存或内置目录。
4. 对央视和卫视分别做逐路出画测试。首帧成功后再观察几分钟，确认稳定性和音画同步。

频道目录加载与节目流播放是两项检查。1.1 已针对前者加入兜底；后者仍取决于四川移动到各直播服务器的连通性、权限、编码与电视解码能力，不能仅凭目录文件推定成功。
